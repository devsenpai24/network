## 6. Routing Protocol

**Choice:** `Multi-area OSPF + eBGP`

**Justification:** Triggered by: multiple autonomous systems (3 ASes require eBGP inter-AS routing per RFC 4271); cloud VPC attachment (eBGP used for cloud provider peering, e.g. AWS Transit Gateway or Azure ExpressRoute). Multi-area OSPF (RFC 2328) partitions the routing domain into areas, reducing SPF computation scope and enabling route summarisation at Area Border Routers (ABRs). eBGP (RFC 4271) handles inter-AS path exchange and cloud provider peering with full policy control (route-maps, local-preference, MED). Together they provide routing-domain isolation, scalable summarisation, and policy-based inter-domain routing.
